# ADR 0020: Career privacy — export, scoped deletion with tombstones, retention disclosure

Status: accepted (2026-10-05, ticket #392, spec #376). Builds on every career ADR (0006–0019).

## Decision
- **Single registry.** `CareerPrivateDataService.CoveredEntityTypes` stays the one list. A test reflects over `ApplicationDbContext` and fails if any `Career*`/`ResumeDocument` entity is missing from it, and another fails if any covered type is missing from the export. New aggregates therefore cannot ship without purge + export coverage.
- **Export.** `GET /api/career/privacy/export` → `application/json` attachment (`Cache-Control: no-store, private`), format `career-export/v1` documented in `docs/career/api-privacy.md`: `{ format, generatedAt, ownerId, sections: { <entityName>: [rows] } }`, one section per covered type, owner-scoped, provenance fields (fact ids, pinned versions, source) kept. Binary blobs (export files, resume upload bytes) are listed by metadata only, not embedded. There is no conversation store; the doc says so.
- **Deletion scopes.** `POST /api/career/privacy/deletions { scope: "raw_documents"|"career_profile" }` and account deletion. Requires recent authentication: the JWT `auth_time`/`iat` must be ≤ 10 min old, else 401 `CareerReauthRequired`. `raw_documents` removes `ResumeDocument` bytes/rows (and proposals' source excerpts); `career_profile` removes every covered career row. Neither touches photo-only data (`UserProfile`, images, packages) or billing (`Payment*`, Stripe records).
- **Purge job + status.** A `CareerDeletionRequest` row (owner, scope, status `pending|in_progress|completed|failed`, attempts, lastError, timestamps) is created; access is revoked immediately by a `CareerTombstone` (owner, scope, createdAt) that all career reads/writes check (403 `CareerDataDeleted` for career_profile scope until a new profile is started? no: tombstone blocks *resurrection*, not new data — see next). Active runs are cancelled before rows are removed. Blob deletes (storage) are retried with backoff up to 5 attempts; status is `completed` only when every row and blob is gone, otherwise `failed` with a visible reason and a retry endpoint `POST …/deletions/{id}/retry`. `GET …/deletions/{id}` shows status. UI never claims deletion while status is not `completed`.
- **No resurrection.** The run runner's fenced finish save checks for a tombstone created after the run started and discards the result. Backup restore: `CareerTombstoneReplayer.ApplyAsync()` re-runs purges for all tombstones and is invoked at startup (idempotent), so a restored backup cannot bring deleted career data back.
- **Account deletion.** `ProfileController.DeleteUserAccount` and `AdminService` user deletion call `DeleteAllForOwnerAsync` with tombstone before removing the user; a purge failure aborts account deletion with an error rather than leaving orphaned career data.
- **Retention disclosure.** `GET /api/career/privacy/retention` returns the actual policy (career rows: until deleted or account deletion; exports: 24 h; raw uploads: until deleted; text processing provider: OpenAI only for runs that use a model, no training; backups: provider default stated as "up to 35 days", restores replay tombstones). The UI privacy page renders it.
