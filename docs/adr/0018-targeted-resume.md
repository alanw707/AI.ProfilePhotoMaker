# ADR 0018: Targeted resumes are assembled from confirmed facts, with provenance per line

Status: accepted (2026-10-05, ticket #389, spec #376). Builds on ADR 0006 (profile versions), ADR 0009 (runtime), ADR 0016 (pinning/stale).

## Decision
- **Facts are addressable.** A confirmed `CareerProfileVersion` exposes fact ids: `title`, `industry`, `years`, `location`, `summary`, `skill:<i>`, `highlight:<i>` (0-based index in that version). Every generated line carries `factIds` (≥ 1) that resolve against the pinned profile version; the server rejects any generated or agent-proposed line whose fact ids do not resolve (`CareerResumeUnsupportedClaim`).
- **Run task `targeted_resume`**, deterministic and model-free (allowance released): needs a confirmed profile and a goal with a confirmed occupation (409 `CareerOccupationRequired`). It selects and orders highlights and skills by overlap with the target occupation's O*NET task/skill words, writes a headline from `title` + target occupation title (`factIds: [title]`, target title cited as the goal), and copies highlight text verbatim (no rewriting, so no invented numbers). A highlight with no digit becomes a **question** (`"What result or scale can you add to: …?"`), stored separately and never merged into copy until the user answers by editing. Fact text is treated as data: instructions inside it are copied as text, never followed, and markup is rendered as text.
- **Material and versions.** `CareerMaterial` (kind `resume`, owner-scoped, title, pinned profile/goal versions + occupation code, contact selection, status `draft`) with immutable `CareerMaterialVersion` rows (`number`, `sections` JSON of lines `{ id, text, factIds, origin: generated|human }`, `author: agent|user`, `createdAt`). The material has a `RowVersion`; saves need `If-Match: "material-vN"` (428/412), so human edits are never silently overwritten. A run started for an existing material (`materialId`) produces a **proposal** (diff of lines vs the current version) instead of a new version; applying needs the If-Match of the version it was based on — a human save in between makes it 412 `stale`, never overwriting human text. Human-edited lines are `origin: human` and keep `factIds` they had (may be empty: human text is the user's own claim).
- **Stale.** Reads compute `stale` with reasons (`profile_changed`, `goal_changed`) from the pinned versions; nothing is deleted or rewritten.
- **Contact and photo.** Default contact selection is name + email only; phone, location and links are off until the user turns them on. No photo field exists on the resume.
- **Limits.** ≤ 60 lines, line ≤ 600 chars, ≤ 200 versions listed (newest first, paged by 50). Privacy: owner cascade, `CareerPrivateDataService` coverage.
