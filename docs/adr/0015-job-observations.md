# ADR 0015: Job observations are live, attributed, link-out only

Status: accepted (2026-10-05, ticket #386, spec #376). Uses the #383 provider qualification and the #385 comparison payload.

## Context

#386 shows observed opportunities for the confirmed occupation with location and remote restrictions, linking to the original listing and never submitting anything. #383 qualified providers and found that **no source grants rights for ongoing commercial aggregation and retention**; it graded USAJOBS as "supplemental federal opportunities only, stand-alone redistribution prohibited". #386 must therefore be built so those constraints hold by construction.

## Decision

- **Source and rights.** `IJobObservationSource` is the seam; `UsaJobsObservationSource` is the only real implementation and is enabled by configuration (`USAJobs:ApiKey` plus `USAJobs:Email`, which USAJOBS requires as the `User-Agent`). Its terms permit internal normalization and deduplication **with displayed values unchanged**, plus attribution and a return link, and forbid stand-alone redistribution. So: displayed figures are copied from the provider verbatim, every observation carries a `sourceUrl` link out, the page attributes USAJOBS and links to it, and pagination is bounded (one page, a provider `ResultsPerPage` cap, `Page` fixed at 1) — no bulk harvesting.
- **Nothing is persisted.** There is no database entity and no cache file: observations are fetched per request, normalized in memory and returned. That is the rights-safe default, it avoids a retention question for third-party content, and it means no private entity is added (deletion/export rules are unaffected). If a future licensed provider permits caching, that is a new decision with a retention policy, not a silent change.
- **No key means an honest unavailable state, not a failure.** With no key configured the source reports `available: false`, reason `source_not_configured`; the endpoint answers 200 with that coverage block and an empty list, the page shows the coverage-unavailable state, and the benchmark pages (brief, pay analysis, market comparison) keep working exactly as before. A provider outage maps to reason `source_unavailable` the same way.
- **Coverage is stated, not implied.** The payload's `coverage` block carries the provider name, the coverage text ("U.S. federal agencies only; not the private-sector market" for USAJOBS), the attribution string, the retrieval time, and the counts of what was excluded. Observed-posting counts are labelled as *observations*, never as employment stock, projections or a vacancy rate, and the copy says a posting list is not the labour market.
- **Eligibility and remote honesty.** Each observation gets `remoteEligibility` = `eligible` (the provider states remote is available), `ineligible` (the posting is tied to a location the user's stated area does not cover) or `unknown` (no reliable restriction field). An eligible-only filter **never** passes an `unknown` observation: unknown stays unknown, and the excluded count is reported.
- **Location rules.** A multi-location posting is one observation with all locations listed; it is eligible when any listed location matches the user's stated area, and the payload says which. Locations are compared against the goal's preferred area or its location text, and a mismatch between the saved preference and the current filter is reported as `preferencesStale: true` rather than silently refiltering.
- **Deduplication and expiry.** Duplicate provider ids are dropped; reposts (same agency, title, locations and pay range) are dropped after the first and counted. A posting whose close date has passed is `expired`, excluded by default and counted; an expired pay range is not shown as current.
- **Untrusted content.** Listing text is data: it is rendered as text by the template (never as HTML), truncated to bounded lengths, and never parsed for instructions. The only outbound URL is the provider's own posting link, validated as an `https` URL on the provider's host allowlist, rendered with `rel="noopener noreferrer"`, and fetched by nobody — the app performs no arbitrary URL fetching, and there is no application, outreach or submission action anywhere in this slice.
- **Bounded and deterministic.** Results are sorted by posted date then provider id, capped, and the response reports `truncated`. The adapter has a timeout inside the request budget and retries once on a transient failure; a timeout or error yields the unavailable coverage state rather than a partial, unlabelled list.

## Consequences

- Enabling the feature is an operator decision (a USAJOBS key; free, but a key request) and a config change, not a code change.
- A licensed commercial feed later replaces the adapter and adds a persistence/retention decision; the payload shape and the honesty rules stay.
