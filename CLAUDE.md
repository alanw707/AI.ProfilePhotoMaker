- **Enhanced Photo Feature**: Now uses consistent webhook pattern (previously conditional HTTP/HTTPS)

- **Reliability**: Unified architecture eliminates conditional polling logic

## Environment-Specific Secret Requirements

### 🔧 Development Environment
**Required Secrets:**
- `JWT_SECRET` (minimum 32 characters)
- `REPLICATE_API_TOKEN` (starts with 'r8_')
- `REPLICATE_WEBHOOK_SECRET` (**CRITICAL**: Required for all webhook operations including enhance photo)
- `MSSQL_SA_PASSWORD` (8+ chars with complexity) OR `ConnectionStrings__DefaultConnection`
- `GOOGLE_CLIENT_ID` (format: 123456789-abc123.apps.googleusercontent.com)
- `GOOGLE_CLIENT_SECRET` (starts with 'GOCSPX-')

**Optional Secrets:**
- `STRIPE_SECRET_KEY` (for payment testing)

**Infrastructure-Generated:**
- `AZURE_STORAGE_CONNECTION_STRING` (generated by Bicep infrastructure, not a secret)
- `AZURE_STORAGE_CONTAINER_NAME` (generated by Bicep infrastructure, not a secret)

### 🎯 Production/Staging Environments
**Required Secrets:**
- All development requirements (except AZURE_STORAGE_* which are infrastructure-generated)

**Infrastructure-Generated (Automatic):**
- `AZURE_STORAGE_CONNECTION_STRING` (**CRITICAL**: Auto-generated by Bicep from storage account)
- `AZURE_STORAGE_CONTAINER_NAME` (**CRITICAL**: Set to 'profile-images' by Bicep infrastructure)

**Pre-Deployment Validation:**
```bash
# Validate secrets before deployment
./scripts/validate-secrets.sh Production

# Development validation
./scripts/validate-secrets.sh Development
```

### ⚠️ Critical Notes
- **Azure Storage is infrastructure-generated** (Bicep automatically creates connection strings from storage account)
- **Never manually set AZURE_STORAGE_* secrets** in GitHub Actions (they're generated by deployment)
- **Azure Storage failures cause 500 errors** due to inaccessible `/uploads` paths
- **Always run secret validation before deployment** to prevent production incidents
- **HTTPS Required for Webhooks**: All Replicate webhook endpoints must use HTTPS for security
- **Webhook Secret**: `REPLICATE_WEBHOOK_SECRET` must be configured in all environments for webhook validation
- Never directly commit to main branch when making changes

## Azure Storage Architecture

### 🏗️ Infrastructure-Generated Pattern
**Design Decision**: Azure Storage credentials are dynamically generated by Bicep infrastructure, not provided as GitHub secrets.

**Implementation**:
- Bicep creates storage account during deployment
- Connection string auto-generated from `storageAccount.listKeys()` 
- Provides multiple naming patterns for compatibility:
  - `ConnectionStrings__AzureStorage` (ASP.NET Core pattern)
  - `AzureStorage__ConnectionString` (alternative pattern)  
  - `AZURE_STORAGE_CONNECTION_STRING` (direct environment variable)

**Benefits**:
- ✅ Automatic key rotation when storage account changes
- ✅ No manual secret management required
- ✅ Eliminates drift between secrets and actual storage account
- ✅ Infrastructure and application stay synchronized automatically

**Previous Issues Resolved**:
- Configuration drift between GitHub secrets and infrastructure
- False-positive validation failures for "missing" secrets that were actually generated
- Manual secret management overhead
