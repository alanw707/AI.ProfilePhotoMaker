# Goal Prompt

=== Goal ===
Objective: Implement the OpenAI Images 2 pivot for AI.ProfilePhotoMaker so the primary product path becomes OpenAI-first instant headshot generation, with Replicate custom model training preserved as a fallback/advanced flow during rollout.

Success criteria:
- A feature-flagged OpenAI instant headshot flow works from one-photo upload through generation, storage, preview/gallery display, download, and regenerate where applicable.
- Backend has a provider abstraction and authenticated `/api/headshots/generate` path, with configurable OpenAI model/endpoint and clear separation from Replicate-specific routes.
- Credits are handled safely: sufficient-balance checks, deterministic consumption, and refund/no permanent charge on provider failure.
- Generated outputs store provider/model metadata sufficient for audit, gallery, retention, and future provider comparisons.
- Frontend default funnel no longer requires training/model steps when OpenAI headshot MVP flag is enabled; Replicate training remains functional and accessible/hidden by feature flag.
- Relevant backend, frontend, and mocked E2E/integration tests are added or updated; known test gaps/failures are documented if blocked.
- Product/operations/docs copy is updated to reflect OpenAI-first flow and Replicate fallback/advanced positioning.
- No secrets or unsafe local config are committed.

Boundaries:
- In scope: execute the implementation plan in `docs/openai-images-2-pivot-implementation-plan.md`, including feature flags, provider abstraction, API endpoint, UI funnel pivot, credits, storage metadata, tests, docs, and rollout notes.
- In scope: preserve current local WIP safely by creating/using a dedicated branch and separating unrelated changes where practical.
- Out of scope for first pass: deleting Replicate backend, fully retiring custom training, large-scale SEO/marketing rewrite beyond necessary product copy, and committing production OpenAI secrets.
- Out of scope unless explicitly approved: irreversible data migrations, public production rollout, or removing active user access to existing trained-model workflows.

Constraints:
- Keep rollout reversible by feature flag/config.
- Preserve Replicate custom model training/generation functionality during the pivot.
- Do not commit secrets; verify config files and diffs before commits.
- Confirm exact OpenAI Images 2 model identifier/API parameters before production-facing implementation assumptions.
- Follow existing project architecture and testing conventions where possible.
- Use `docs/openai-images-2-pivot-implementation-plan.md` as the task breakdown source.
