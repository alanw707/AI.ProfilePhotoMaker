# Root Cause Analysis: OAuth 500 Internal Server Error in Production

## Executive Summary

The OAuth endpoint (`/api/auth/external-login/google`) in production is returning 500 Internal Server Errors because the required Google OAuth environment variables (`GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`) are not configured in the Azure Container Apps deployment, causing the application to fail when attempting to process OAuth requests.

## Issue Details

- **Symptom**: OAuth endpoint returns HTTP 500 error with empty response body
- **Impact**: Users cannot log in using Google OAuth in production
- **Duration**: Ongoing since deployment
- **Environment**: Production (Azure Container Apps)
- **Affected Endpoint**: `https://api.aiprofilephotomaker.com/api/auth/external-login/google`

## Root Cause

The Google OAuth environment variables are not configured in the Azure Container Apps deployment template (`simple-deploy.bicep`). When the OAuth endpoint is accessed:

1. Application checks for `Authentication:Google:ClientId` in configuration - not found
2. Falls back to `Environment.GetEnvironmentVariable("GOOGLE_CLIENT_ID")` - returns null
3. OAuth configuration validation fails with `string.IsNullOrEmpty()` check
4. Application returns HTTP 500 error due to missing configuration

### Code Flow Analysis

```csharp
// Program.cs line 173-174
var googleClientId = string.IsNullOrEmpty(configClientId) 
    ? Environment.GetEnvironmentVariable("GOOGLE_CLIENT_ID") 
    : configClientId;

// AuthController.cs line 108-113
var configClientId = _configuration["Authentication:Google:ClientId"];
var clientId = string.IsNullOrEmpty(configClientId) 
    ? Environment.GetEnvironmentVariable("GOOGLE_CLIENT_ID") 
    : configClientId;
if (string.IsNullOrEmpty(clientId))
{
    return BadRequest(new { error = "Google OAuth is not configured" });
}
```

Without the environment variables, `clientId` is null, but the code doesn't reach the BadRequest response - it fails earlier in the middleware pipeline.

## Resolution Steps

### Immediate Fix (Required)

1. **Add OAuth Environment Variables to Container App**
```bash
# Add Google OAuth credentials to the Container App
az containerapp update \
  --name aipm-api-v1 \
  --resource-group aiprofilemaker-v1 \
  --set-env-vars \
    GOOGLE_CLIENT_ID="your-google-client-id" \
    GOOGLE_CLIENT_SECRET="your-google-client-secret"
```

2. **Verify Configuration**
```bash
# Confirm variables are set
az containerapp show --name aipm-api-v1 --resource-group aiprofilemaker-v1 \
  --query "properties.template.containers[0].env[?name=='GOOGLE_CLIENT_ID' || name=='GOOGLE_CLIENT_SECRET'].name" -o json
```

3. **Test OAuth Endpoint**
```bash
# Test the OAuth endpoint
curl -v https://api.aiprofilephotomaker.com/api/auth/external-login/google
# Should return HTTP 302 redirect to Google OAuth
```

### Permanent Fix (Infrastructure)

Update `infrastructure/simple-deploy.bicep` to include OAuth configuration:

```bicep
// Add to container env section (around line 310)
{
  name: 'GOOGLE_CLIENT_ID'
  secretRef: 'google-client-id'
}
{
  name: 'GOOGLE_CLIENT_SECRET'
  secretRef: 'google-client-secret'
}

// Add to secrets section (around line 282)
{
  name: 'google-client-id'
  value: googleClientId
}
{
  name: 'google-client-secret'
  value: googleClientSecret
}
```

Add parameters to the template:
```bicep
@secure()
param googleClientId string

@secure()
param googleClientSecret string
```

## Lessons Learned

1. **Missing Configuration Management**: OAuth credentials were not included in the deployment template despite code expecting them
2. **Insufficient Error Handling**: The application should provide clearer error messages for missing configuration
3. **Deployment Validation Gap**: No automated check for required environment variables post-deployment
4. **Documentation Gap**: OAuth configuration requirements not documented in deployment guides

## Recommendations

## Conclusion

The root cause is a deployment configuration issue where Google OAuth credentials are missing from the Azure Container Apps environment variables. This is a straightforward configuration fix that requires adding the OAuth credentials to the container environment and updating the deployment template for future deployments.

The code itself is correct and includes proper fallback logic. Once the environment variables are configured, OAuth will function as expected.
