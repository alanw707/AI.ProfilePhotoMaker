# Root Cause Analysis: OAuth 500 Internal Server Error

## Executive Summary

The OAuth endpoint (`/api/auth/external-login/google`) was returning HTTP 500 Internal Server Error despite having complete Google OAuth credentials configured. The root cause was a **missing JWT_SECRET environment variable** that prevented the entire application from starting properly, causing all dynamic endpoints to fail while static endpoints remained functional.

## Issue Details

### Symptoms
- OAuth endpoint returning HTTP 500 with empty response body
- All OAuth-related endpoints failing silently
- Health check endpoint working normally
- Debug endpoints accessible but OAuth flow broken
- No redirect to Google OAuth authorization page

### Impact
- **Severity**: Critical
- **Duration**: Unknown (discovered during investigation)
- **Affected Services**: OAuth authentication, user registration via Google
- **User Impact**: Complete inability to use Google Sign-In functionality

## Investigation Process

### Step 1: Initial Discovery
- Confirmed OAuth endpoint returning 500 error across all platforms
- Verified Google OAuth credentials were properly set:
  - `GOOGLE_CLIENT_ID`: ✅ Configured
  - `GOOGLE_CLIENT_SECRET`: ✅ Configured
- Identified discrepancy: credentials present but OAuth still failing

    var jwtSecret = GetEnvironmentVariable(JWT_SECRET) ?? _configuration["JWT:Secret"];
    
    if (string.IsNullOrEmpty(jwtSecret))
    {
        results.Add(new ValidationResult(false, JWT_SECRET, "JWT secret is required"));
        return;
    }

    }
}

## Root Cause

**Primary Cause**: Missing or inadequate JWT_SECRET environment variable
- The JWT_SECRET was configured as a secret reference but the actual secret value was either missing or too short
- Environment validation at startup prevented the application from initializing properly
- This caused a cascade failure affecting all dynamic endpoints including OAuth

**Contributing Factors**:
1. Silent failure mode - application partially starts but doesn't properly handle validation errors
2. Misleading error response - HTTP 500 with empty body provides no diagnostic information
3. Health endpoint remains functional, creating false positive for monitoring

## Resolution

### Immediate Fix Applied
```bash
# Generate secure JWT secret (48 bytes base64 encoded)
JWT_SECRET=$(openssl rand -base64 48)

# Update Azure Container App secret
az containerapp secret set \
  --name aipm-api-v1 \
  --resource-group aiprofilemaker-v1 \
  --secrets jwt-secret="$JWT_SECRET"

# Update container environment variable reference
az containerapp update \
  --name aipm-api-v1 \
  --resource-group aiprofilemaker-v1 \
  --set-env-vars JWT__Secret=secretref:jwt-secret
```

### Verification
- OAuth endpoint now returns HTTP 302 (redirect) as expected
- Redirect URL properly formed with Google OAuth parameters
- All authentication schemes properly registered
- Application fully functional

## Lessons Learned

### What Went Well
- Systematic investigation approach quickly identified the issue
- Debug endpoints provided valuable diagnostic information
- Azure Container Apps logs contained clear error messages

2. **Health Checks**: Should validate critical dependencies like JWT configuration
3. **Deployment Validation**: Pre-deployment checks should verify all required secrets
4. **Documentation**: Environment variable requirements should be clearly documented

## Conclusion

The OAuth 500 error was caused by a missing JWT_SECRET environment variable that prevented the application from starting properly. While the Google OAuth credentials were correctly configured, the application's startup validation failed due to the missing JWT configuration, causing all dynamic endpoints to fail.

The issue has been resolved by generating and setting a proper JWT secret. This incident highlights the importance of:
1. Comprehensive environment validation before deployment
2. Clear error messaging for configuration failures
3. Proper health checks that validate critical dependencies
4. Documentation of all required environment variables
