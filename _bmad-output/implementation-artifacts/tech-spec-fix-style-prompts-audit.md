# Tech-Spec: Fix Style Prompts — Data Drift, Casual Nudity Fix, and Full Prompt Quality Audit

**Created:** 2026-02-20

## Overview

### Problem Statement

Three interrelated issues with the AI photo generation style prompts:

1. **Casual style generates shirtless photos**: The "casual" style (Id 14) prompt mentions "everyday clothing" but the negative prompt lacks explicit anti-nudity terms (`shirtless, bare chest, topless`, etc.), causing the FLUX model with LoRA training to sometimes generate bare-chested results for male subjects.

2. **Data drift on Ids 1 & 3**: The `UpdateFunLifestyleStyles` migration (Sep 2025) renamed Id 1 from "corporate" → "beach-vibes" and Id 3 from "consultant" → "fresh", with matching prompts. However, the EF `HasData()` model in `ApplicationDbContext.SeedStyles()` was never updated — it still defines Id 1 as "corporate" and Id 3 as "consultant". Every subsequent migration auto-generates `UpdateData` calls that overwrite the `PromptTemplate` and `NegativePromptTemplate` columns back to corporate/consultant values, while leaving the Name and Description as beach-vibes/fresh. Result: users select "Beach Vibes" but get corporate headshots; users select "Fresh" but get consultant portraits.

3. **Weak negative prompts across multiple styles**: Several styles have dangerously thin negative prompts lacking quality guards, anatomy guards, and nudity blockers:
   - `edgy-urban` (Id 16): "conservative formal, traditional business, bland conventional" — 3 terms only
   - `fitness` (Id 19): "sedentary look, unhealthy appearance, low energy" — 3 terms only
   - `glamour` (Id 17): "casual simple, plain appearance, understated look" — 3 terms only
   - `influencer` (Id 11): missing anatomy, quality, nudity guards
   - `digital-nomad` (Id 12): missing anatomy, quality, nudity guards
   - `digital-native` (Id 21): "outdated technology, old fashioned, formal business, analog aesthetic, traditional office" — 5 terms, no quality/anatomy guards
   - `medical` (Id 6): moderate — missing nudity guards

4. **Stale config references**: `appsettings.json` `ProStyles` still lists "corporate" and "consultant" (no longer exist as style names). `CasualRelaxedStyles` is missing "beach-vibes" and "fresh". This means beach-vibes and fresh get default tuning (3.0/28) instead of casual tuning (2.3/40).

5. **Broken fallback chain**: `ReplicateApiClient.GetStylePromptsFromDatabase()` and `MockReplicateApiClient.GetStylePromptsFromDatabase()` both fall back to "corporate" when a style isn't found — but "corporate" no longer exists in the DB.

### Solution

Create a DB migration and fix the EF model seed data to:

1. **Resolve data drift** — Update `HasData()` in `ApplicationDbContext.SeedStyles()` to define Id 1 as "beach-vibes" and Id 3 as "fresh" with proper prompts. Eliminate all references to "corporate" and "consultant". Create a migration that fixes the live DB.
2. **Fix casual nudity** — Add explicit anti-shirtless/nudity terms to the casual style's negative prompt.
3. **Fix fresh style** — Restore proper fresh prompt matching the "clean energetic refreshed" aesthetic. Shirtless is allowed for this style.
4. **Full negative prompt audit** — Bring all 20 styles up to a consistent quality baseline in their negative prompts (anatomy, quality, skin realism guards).
5. **Config updates** — Fix `appsettings.json` to remove corporate/consultant from ProStyles, add beach-vibes and fresh to CasualRelaxedStyles. Fix `style-preview.service.ts` known styles list. Fix fallback chain in both `ReplicateApiClient` and `MockReplicateApiClient`.
6. **Test updates** — Update `StylePromptTokenValidationTests` and `ReplicateApiClientStyleTuningTests` to reflect eliminated corporate/consultant.

## Context for Development

### Codebase Patterns

**Prompt flow (DB → API):**
1. `StyleController.GetStyles()` returns active styles (Id, Name, Description) to frontend — no auth required
2. User selects styles → `StyleController.SelectStyles()` saves selections
3. On generation, `ReplicateApiClient.GenerateImagesAsync()` calls `GetStylePromptsFromDatabase(styleName)` to fetch `PromptTemplate` + `NegativePromptTemplate`
4. `CreateFluxStylePrompt()` replaces `{subject}` with trigger word `user_{userId}`, `{gender}` and `{ethnicity}` from UserInfo
5. `CreateFluxNegativePrompt()` replaces same placeholders + auto-appends blemish guard: `", moles, dark spots, skin blemishes, birthmarks, skin spots"`
6. `ApplyRealismModifier()` randomly appends one of 6 realism modifiers to positive prompt
7. `ResolveStyleTuning()` picks guidance_scale + num_inference_steps based on `appsettings.json` ProStyles/CasualRelaxedStyles membership

**Seed data pattern:**
- `ApplicationDbContext.SeedStyles()` (line 448) uses `HasData()` with hardcoded Style objects
- EF Core auto-generates `UpdateData` calls in every migration to sync DB with seed — this is what causes drift when seed doesn't match runtime data
- Fix: update the seed to match intended state, then scaffold a migration that will reconcile

**Migration pattern for prompt changes:**
- Raw SQL via `migrationBuilder.Sql()` — see `UpdateStyleTuningAndCleanup`, `FixSkinBlemishAndWaxyForehead`
- For this change: update HasData() first, then scaffold migration. The auto-generated migration will contain UpdateData calls for Ids 1 & 3 (name, description, prompts). Additionally, add raw SQL for the negative prompt audit changes across all styles.
